# KI-012 原子式 Stage 候選表所有權失敗保護

Stage writer 用 UUID 產生 `__bl001_stage_* ` 候選表。即使 UUID 碰撞的機率極低，`pandas.to_sql(..., if_exists="fail")` 一旦因表名已存在而拒絕寫入，原本的錯誤處理仍可能直接執行 `DROP TABLE IF EXISTS`，誤刪另一個 writer 已經建立的同名表。

新的錯誤處理只有在**本次 `to_sql` 已完整正常回傳**後，才將候選表標記為本次擁有、允許在後續 swap/索引錯誤時清理它；如 `to_sql` 在建表途中失敗，**保留候選表供離線人工判讀**，不假定它屬於本次 writer。這會在部分失敗情境留下更多候選表，但避免以不可靠的所有權猜測刪除資料。

私人 SQLite 驗證包含：固定 UUID 模擬既有候選表衝突（他人資料不可刪除），以及模擬 `to_sql` 建表後才失敗（保留未證實擁有的候選表；舊 `sampleSrc` 及索引不變）。這不是自動候選表清理授權；不操作正式 WorkPool。
