# KI-012 一鍵快檢：多筆 JSON 狀態不能互相掩蓋

某些子程序可能先輸出 `{"status":"FAIL"}`，最後又輸出 `{"status":"PASS"}` 並錯誤地回傳 exit 0。過去一鍵快檢只看最後一筆 JSON 的 `status`，可能把曾明確回報失敗的子程序視為成功。

現在對所有 JSON 狀態型子檢查，逐行取出可解析 JSON 物件中的 `status`；只有至少一筆狀態，而且**每一筆狀態都與該檢查的精確預期值相符**，才會繼續。否則整體回報 `FAIL`，跳過後續子檢查及實際模型自檢。非 JSON 一般 log 仍可存在，不能藉由最後印出 PASS 掩蓋先前的失敗。

此項純粹調整驗收結果的解析方式，**不改變**私人測試範圍、缺模型時 `PASS_PARTIAL_NO_REAL_MODEL` 的不完整判定、或正式 WorkPool 未驗收的限制。
