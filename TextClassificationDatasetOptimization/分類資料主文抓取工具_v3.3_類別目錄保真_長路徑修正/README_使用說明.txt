分類資料主文抓取工具 v3.3（類別目錄保真／長路徑修正版）
========================

支援來源
--------
1. 舊式單篇來源：
   - 原文標題／原文連結
2. 新式單篇來源：
   - 來源標題（原文）／原文／索引連結
3. Bing News 搜尋結果集合：
   - 來源型態含「公開新聞搜尋索引」或「候選來源集合」
   - URL 為 https://www.bing.com/news/search?...

處理方式
--------
- 單篇來源會直接下載並抽取正文。
- Bing News 搜尋集合會解析 RSS 與搜尋頁 HTML，合併可取得的候選文章並去重。
- 搜尋頁本身不會被當成正文保存。
- 展開後的每篇候選文章會逐一下載，清除廣告、導覽列、推薦區與頁尾等雜訊。
- 同一類別內相同文章網址只保留一次。
- 每個 TXT 只保留清理後正文，不寫入 #T#[類別]、來源網址或元素據摘要。
- 類別由外層 #T#[類別] 目錄表示。
- 進入文章抓取階段後，每完成一篇就立即寫入 TXT。
- 抓取結果.csv 也會逐筆追加並立即刷新到磁碟。

正式模式（預設）
----------------
把來源元素據 ZIP 拖曳到「一鍵抓取主文.bat」。

正式模式預設：
- 每個搜尋集合：不設程式端篇數上限。
- 每個類別：不設篇數上限。

這裡的「不限」是指程式不主動截斷；實際篇數仍取決於 Bing RSS／HTML 當次回傳多少候選結果，以及網站是否能正常存取。

測試模式
--------
把來源元素據 ZIP 拖曳到「測試模式抓取.bat」。

測試模式固定：
- 每個搜尋集合最多展開 10 篇。
- 每個類別最多保留 20 篇。

也可以在命令列使用：

  python scrape_articles.py --input-zip "來源包.zip" --test-mode

或：

  一鍵抓取主文.bat "來源包.zip" test

重要參數
--------
正式模式的預設值均為 0，0 表示不限：

  --max-results-per-index 0
  --max-articles-per-category 0

要自行指定正式模式上限，例如每個索引 30 篇、每類 500 篇：

  --max-results-per-index 30 --max-articles-per-category 500

開啟測試模式：

  --test-mode

注意：開啟 --test-mode 時，程式固定使用 10／20；即使命令列另傳其他上限，也以測試模式限制為準。

同類別內依網址去重（預設）：

  --dedupe-scope category

所有類別共用去重：

  --dedupe-scope global

不依網址去重：

  --dedupe-scope none

只處理單篇來源、不展開搜尋集合：

  --skip-search-index

Windows 輸出
------------
輸出會放在來源 ZIP 同一層：

正式模式：
  主文資料包_YYYYMMDD_HHMMSS\
  主文資料包_YYYYMMDD_HHMMSS.zip

測試模式：
  主文資料包_測試_YYYYMMDD_HHMMSS\
  主文資料包_測試_YYYYMMDD_HHMMSS.zip

另有：
  主文抓取紀錄_模式_YYYYMMDD_HHMMSS\

即時存檔與中途停止
------------------
- 搜尋索引會先展開；畫面顯示 [INDEX ...] 時，尚未開始下載單篇正文。
- 進入 [ARTICLE ...] 階段後，每完成一篇就立刻產生 TXT。
- 抓取結果.csv 會同步逐筆寫入；中途關閉時，已完成的 TXT 與 CSV 記錄仍會保留。
- 最終 ZIP 與抓取摘要.txt 仍需等整次工作正常結束後才會建立。

輸出紀錄
--------
- 抓取結果.csv：每篇文章的成功／失敗、字數、輸出檔名與錯誤原因；文章完成時立即追加。
- 索引展開結果.csv：每個搜尋集合展開出的候選文章、順位與網址。
- 抓取摘要.txt：執行模式、上限設定、各類別成功數與整體統計。

限制
----
- 不會繞過登入、付費牆、CAPTCHA、Cloudflare 驗證或 robots.txt 限制。
- JavaScript 動態載入且 HTML 不含正文的網站可能抓不到。
- 「全部展開」不代表能遍歷搜尋引擎所有歷史分頁，而是保留 RSS 與目前搜尋頁可回傳、可解析的全部候選結果。
- Bing 或新聞網站改版後，搜尋結果解析規則可能需要更新。
- 正式投入訓練前，建議抽查部分 TXT、抓取結果.csv 及索引展開結果.csv。

類別目錄與 Windows 長路徑（v3.3）
-------------------------------
- `#T#[正式類別 label]` 目錄名稱不再做 100 字元截斷，也不會加 `__xxxxxxxx` 雜湊。
- 路徑過長時，程式只會縮短文章標題檔名；類別 label 保持完整。
- 預設 `--max-path-chars 240`，保守相容未啟用 Windows Long Paths 的環境。
- 若系統已啟用 Long Paths，可用 `--max-path-chars 0` 停用舊式路徑預算。
- 若類別目錄本身已長到無法在 240 字元安全預算內容納檔名，程式會明確報錯；建議把來源 ZIP／輸出位置移到較短路徑，例如 `C:\AT`。
- 若正式類別 label 含 Windows 不合法字元，程式會拒絕自動替換，以免破壞分類一致性。
