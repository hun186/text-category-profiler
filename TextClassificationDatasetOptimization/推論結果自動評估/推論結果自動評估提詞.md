# 一、務必先理解系統資料結構

系統輸出包含不同層次的資訊，禁止混淆。

## 第一層：片段類別判定

文章會先被切割為多個文本片段。

每個片段由分類模型判定其所屬的「片段類別」。

實際有哪些片段類別，必須以模型輸出與既有系統類別定義為準。

不得自行創造不存在的類別。

---

# 二、Compositions 的正確定義

`Compositions` 是：

> 全文所有已完成分類之片段，其片段類別判定結果的數量統計。

例如：

```json
{
  "CrossStrait Relation": 7
}
```

表示：

> 全文共有 7 個完成片段分類的片段，而且這 7 個片段全部被模型判定為 `CrossStrait Relation`。

如果存在其他片段類別，也會一併列在 `Compositions` 中。

例如：

```json
{
  "Informative": 5,
  "CrossStrait Relation": 3,
  "Exempt": 2
}
```

表示全文共有 10 個片段：

* 5 個判為 Informative；
* 3 個判為 CrossStrait Relation；
* 2 個判為 Exempt。

因此：

> `Compositions` 是全文所有片段分類結果的完整類別數量分布。

不得將 `Compositions` 解讀成：

* 只統計重要片段；
* 只統計與臺灣投資安全相關的片段；
* 文章層級主題；
* 二元議題判定結果。

---

# 三、文章層級二元議題判定

輸出中的下列欄位，例如：

* `General`
* `20Da`
* `APEC`
* `Boao Forum`
* `CrossStraitTree`
* `RUWar`
* `CN Cooperation`
* `CN Military`
* `Navigational Warning-Military`
* `Navigational Warning-Non Traditional Security`
* `FocT`
* `R3`

不是片段分類類別。

它們屬於：

> 完成片段分類及 Composition 分析之後，再依照預先設定好的規則，判斷整篇文章是否符合某一特定議題的文章層級二元判定結果。

概念流程為：

> 文章
> → 切割成片段
> → 片段分類
> → 統計 `Compositions`
> → 套用預設議題規則
> → 產生 General、APEC、CN Military、R3 等文章層級二元議題結果。

禁止將這些二元議題欄位視為：

> `Compositions` 中可能出現的片段類別。

---

# 四、本任務最高優先評估目標：Composition 正確性

本任務最重要的不是判斷文章摘要是否正確，也不是單純判斷文章整體是否涉及某個議題。

最重要的是：

> 模型是否正確判斷各片段的類別，進而形成合理的 `Compositions`。

評估優先順序包括：

1. 各片段實際語意是否符合模型判定類別。
2. 各片段類別數量是否合理。
3. 是否存在片段錯分。
4. 是否存在類別漏判。
5. 是否有某類別被過度判定。
6. 是否有某類別被低估。
7. 是否將不同性質片段錯誤集中到同一類別。
8. 是否有過度寬泛類別吸收了本應屬於更明確類別的片段。
9. `Class Of Most Pieces` 是否合理。
10. `Class Of Highest Score` 是否合理。

---

# 五、Class Of Most Pieces

`Class Of Most Pieces` 表示：

> `Compositions` 中片段數量最多的片段類別。

它不等於：

* 文章最重要主題；
* 投資安全價值最高類別；
* 最高分片段類別；
* 文章層級二元議題。

`Text Of Class Of Most Pieces` 是該類別的代表性文本，可用於協助檢查：

> 模型將主要數量片段判入此類是否合理。

如果多個類別的片段數量相同，而輸入沒有提供 tie-breaking 規則，不得自行假設系統如何選擇。

---

# 六、Class Of Highest Score

`Class Of Highest Score` 表示：

> 全文片段中，取得最高「類別對應分數」之片段所屬類別。

`Class Of Highest Score` 與 `Class Of Most Pieces`：

* 可以相同；
* 也可以不同。

兩者不同本身並不代表模型錯誤。

# 八、片段類別分數的設計原則

每一種片段類別都有事先設定好的分數。

這個分數不是：

* 模型 confidence；
* 模型分類機率；
* 一般新聞熱度；
* 一般新聞重要程度；
* 文字資訊量；
* 文章品質。

而是：

> 此種類型的資訊，從「臺灣投資安全風險評估」角度，是否屬於需要注意的資訊。

分數正負號具有明確語意。

---

# 九、正分、負分與零分

## 正分：需要注意

如果某一類資訊：

> 對臺灣投資安全的風險辨識、預警、情勢研判或決策具有實質價值，

則應給予正分：

`Score > 0`

例如：

* 對臺軍演；
* 臺海封鎖；
* 軍事部署；
* 灰色地帶行動；
* 經濟脅迫；
* 國際制裁；
* 關鍵科技限制；
* 重大供應鏈風險。

注意：

> 正分不表示這是「利多」或「好消息」。

正分只表示：

> 這種類型的資訊是臺灣投資安全評估需要注意的。

---

## 負分：通常無需注意

如果某一類資訊：

> 通常對臺灣投資安全風險分析沒有實質研判價值，或屬於應降低權重的資訊，

則給予負分：

`Score < 0`

注意：

> 負分不是表示「這是負面事件」。

負分代表：

> 通常無需納入臺灣投資安全重點研判。

---

## 零分：難以決定

如果一種類別：

* 有時值得注意；
* 有時不值得注意；
* 高度依賴上下文；
* 僅依類別名稱無法穩定判斷投資安全價值；

則可設定：

`Score = 0`

零分表示：

> 無法單靠這個類別穩定判定其投資安全研判價值。

---

# 十、分數絕對值的意義

分數絕對值代表：

> 此類別「需要注意／無需注意」判斷的明確程度。

原則：

`|Score| 越大 → 判斷越明確。`

因此：

* 高正分：非常明確需要注意。
* 小正分：較可能需要注意，但關聯較間接。
* 0：難以僅依類別判定。
* 小負分：通常較不重要，但仍可能依上下文改變。
* 高負分：非常明確通常無需關注。

---

# 十一、類別粒度與分數絕對值

原則上：

> 類別越明確、越具體、語意越單一，其分數絕對值可以越大。

例如一個非常寬泛的類別：

`CrossStrait Relation`

可能同時包含：

* 軍事；
* 政治；
* 經濟；
* 文化；
* 人員交流；
* 一般評論。

因此僅依這個寬泛類別，很難保證每一篇文本都具有相同的投資安全價值。

相較之下，如果分類更具體，例如：

* 對臺軍演；
* 臺海封鎖；
* 軍事衝突；
* 經濟制裁；
* 半導體出口管制；

這些類別對投資安全的意義更加明確，因此較適合使用較大的分數絕對值。

評估時應注意：

> 如果一個高度寬泛、語意多變的類別被設定為極端高正分或極端高負分，可能存在類別粒度與分數強度不匹配的問題。

---

# 十二、InfoScoreSum、InfoScoreMean、InfoScoreStd

假設全文共有 N 個片段，每個片段依其分類類別取得分數：

S1, S2, ... SN

則：

## InfoScoreSum

代表：

> 所有片段分數加總。

即：

`S1 + S2 + ... + SN`

---

## InfoScoreMean

代表：

> 所有片段分數的平均。

即：

`InfoScoreSum / N`

---

## InfoScoreStd

代表：

> 所有片段分數分布的標準差。

如果：

`InfoScoreStd = 0`

表示：

> 所有片段取得完全相同的分數。

Std 越大，通常表示：

> 全文不同片段的投資安全研判價值差異越大。

---

# 十三、非常重要：輸入只有聚合分數

一般情況下，輸入模型只會看到：

* `InfoScoreSum`
* `InfoScoreMean`
* `InfoScoreStd`
* `Compositions`

但不一定會看到：

* 每個片段實際分數；
* 每個類別預設分數；
* 完整類別分數表。

因此：

> 在多種類別混合的 Composition 中，不得自行從 Sum / Mean / Std 反推出每一種類別各自的分數。

例如：

```json
{
  "ClassA": 5,
  "ClassB": 4,
  "ClassC": 3
}
```

如果只有：

```text
InfoScoreMean = 20
InfoScoreStd = 60
```

不得自行宣稱：

* ClassA 是正分；
* ClassB 是負分；
* ClassC 是零分；

或任何其他具體配置。

因為多種不同分數組合都可能產生相同或近似的聚合統計。

---

# 十四、一般情況評估「整體聚合分數語意」

當無法知道各類別實際分數時，應評估：

> 全文經分類後所形成的「整體 InfoScore 傾向」，是否符合文章實際的臺灣投資安全研判價值。

例如：

文章主要描述：

* 大型對臺軍演；
* 臺海封鎖；
* 解放軍部署；
* 經濟制裁；

理論上屬於：

> 臺灣投資安全需要注意的資訊。

如果：

`InfoScoreMean`

卻呈現高度負值，

則可以指出：

> 整體聚合分數方向可能與文章實際投資安全研判價值不一致。

但在多類別情況下不得因此直接斷定：

> 某一個特定類別分數設定錯誤。

---

# 十五、expected_aggregate_score_polarity

輸出：

`expected_aggregate_score_polarity`

只能使用：

* `"positive"`
* `"zero_or_neutral"`
* `"negative"`
* `"mixed_or_uncertain"`

代表：

> 根據文本實際內容，如果分類與類別分數設計合理，預期整篇文章聚合 InfoScore 大致應呈現何種方向。

# 十六、aggregate_score_semantics_status

輸出：

`aggregate_score_semantics_status`

只能使用：

* `"reasonable"`
* `"possibly_wrong_direction"`
* `"wrong_direction"`
* `"possibly_wrong_magnitude"`
* `"wrong_magnitude"`
* `"wrong_direction_and_magnitude"`
* `"uncertain"`

這個欄位只評估：

> 整篇文章聚合後的 InfoScore 表現是否符合文章實際投資安全研判價值。

它不直接評估某一特定類別的分數。

# 十七、何時可以推論特定類別分數

只有在現有資訊足以直接取得或可靠唯一推導時，才能評論特定類別分數設定。

例如：

## 情況 A：Composition 只有一種類別

```json
{
  "CrossStrait Relation": 7
}
```

同時：

```text
InfoScoreMean = -100
InfoScoreStd = 0
```

由於全文所有 7 個片段都是同一類別，而且全部片段分數相同，因此可以合理推論：

> CrossStrait Relation 在此計分機制下對應 -100 分。

此時才可以進一步評估：

> -100 的分數方向或絕對值是否合理。

---

## 情況 B：輸入直接提供類別分數表

如果輸入另外明確提供：

```json
{
  "CrossStrait Relation": -100,
  "Military Conflict": 100
}
```

則可以直接評估各類別分數。

---

## 情況 C：數學上可以唯一推導

只有當目前資料足以唯一確定特定類別分數時才可以推論。

不得在多個解都可能成立時猜測。

---

# 十八、class_score_mapping_verifiable

輸出：

`class_score_mapping_verifiable`

只能為：

* true
* false

表示：

> 現有輸入是否足以可靠將聚合分數對應回某個特定片段類別的分數。

例如：

單一類別、所有分數相同：

```json
"class_score_mapping_verifiable": true
```

多種類別、沒有類別分數表：

```json
"class_score_mapping_verifiable": false
```

---

# 十九、score_configuration_issue

輸出：

`score_configuration_issue`

允許：

* true
* false
* null

## true

只有在：

> 現有輸入足以知道或可靠推導特定類別使用的分數，而且該分數的正負方向或絕對值明顯不符合臺灣投資安全評估用途。

## false

只有在：

> 特定類別分數可驗證，而且目前沒有明顯問題。

## null

如果：

> 無法從聚合分數可靠還原各類別分數。

注意：

`null`

不是代表分數設定沒有問題，而是：

> 現有資料不足以確認。

---

# 二十、不得把聚合分數異常直接歸因於分數設定

例如文章高度涉及投資安全，但：

`InfoScoreMean = -60`

而 Composition 同時包含多個類別。

此時可以：

```json
"aggregate_score_semantics_status": "possibly_wrong_direction"
```

但不能直接：

```json
"score_configuration_issue": true
```

因為負值也可能來自：

* 模型將部分片段錯分到負分類別；
* 多個類別分數共同造成；
* 類別分數設計本身有問題；
* 或多種因素同時存在。

因此必須保留不確定性。

---

# 二十一、聚合統計數學一致性

另外輸出：

`aggregate_statistics_consistent`

這個欄位只回答：

> Sum、Mean、Std 在目前可驗證範圍內是否數學自洽。

例如：

7 個片段：

```text
Sum = -700
Mean = -100
Std = 0
```

則至少可以確認：

* `-700 / 7 = -100`
* 所有片段分數一致。

但如果 Composition 包含多個類別，而且沒有各類別分數表：

> 不能僅依 Composition 完整驗證 Std 是否與各類別分數配置相符。

因此不要宣稱：

> 所有類別分數設定均已驗證正確。

---

# 二十二、禁止循環驗證

`InfoScoreSum`、`InfoScoreMean`、`InfoScoreStd` 是：

> 片段分類 → 類別對應分數 → 聚合統計

之後產生的結果。

因此禁止：

> Mean 很高
> → 所以文章很重要
> → 所以 Composition 一定正確。

也禁止：

> Mean 很低
> → 所以文章不重要
> → 所以低價值類別一定判對。

正確流程：

> 閱讀文本
> → 判斷片段語意
> → 評估片段分類
> → 評估 Composition
> → 評估文章實際投資安全價值
> → 再檢查聚合分數是否合理。

---

# 二十三、Composition 正確性

輸出：

`composition_status`

只能使用：

* `"correct"`
* `"likely_correct"`
* `"uncertain"`
* `"incorrect"`

## correct

目前證據充分支持片段分類及 Composition。

## likely_correct

整體高度合理，但仍存在少量未直接驗證或邊界性問題。

## uncertain

現有資訊不足以可靠判定。

## incorrect

存在明確或高度可信的：

* 片段錯分；
* 類別漏判；
* 類別過度判定；
* 類別低估；
* 主要類別錯誤；
* Composition 失真。

---

# 二十四、Composition 錯誤類型

輸出：

`composition_error_types`

可複選：

* `"none"`
* `"misclassification"`
* `"missing_class"`
* `"over_classification"`
* `"under_classification"`
* `"wrong_dominant_class"`
* `"wrong_highest_score_class"`
* `"mixed_classes_collapsed"`
* `"composition_count_suspicious"`
* `"insufficient_evidence"`

其中：

### misclassification

片段可能被判入錯誤類別。

### missing_class

文章明顯存在某類片段，但 Composition 未反映。

### over_classification

某一類別片段數量可能被高估。

### under_classification

某一類別片段數量可能被低估。

### wrong_dominant_class

`Class Of Most Pieces` 可能錯誤。

### wrong_highest_score_class

`Class Of Highest Score` 可能錯誤。

### mixed_classes_collapsed

不同性質片段被過度集中到同一類別。

### composition_count_suspicious

Composition 的片段數量或比例存在疑點。

### insufficient_evidence

現有資料不足以完成可靠驗證。

---

# 二十五、composition_model_issue

輸出：

`composition_model_issue`

允許：

* true
* false
* null

## true

有證據顯示問題可能位於：

> 片段分類模型或 Composition 形成結果。

例如：

* 片段語意與分類不符；
* 某類大量過度分類；
* 某類大量漏判；
* 混合類型被壓成單一類；
* 模型選擇過度寬泛類別；
* Dominant Class 因錯分而失真。

## false

Composition 本身看起來合理。

## null

證據不足以判斷。

---

# 二十六、二元議題規則獨立評估

Composition 與：

* General
* APEC
* CN Military
* R3
* 等文章層級二元議題

必須分開評估。

如果 Composition 本身正確，但二元議題結果不合理：

> 問題可能在二元議題規則。

如果 Composition 已經錯誤：

> 二元結果異常可能只是上游分類錯誤造成的連鎖結果。

---

# 二十七、binary_rule_issue

輸出：

`binary_rule_issue`

允許：

* true
* false
* null

## true

Composition 合理，但二元議題結果依已知規則仍明顯不合理。

## false

有足夠資訊顯示規則結果合理。

## null

沒有提供實際二元議題規則，或不足以確認。

不得僅依一般常識自行發明觸發規則。

---

# 二十八、三種問題來源必須分開

請分開判斷：

1. `composition_model_issue`
2. `score_configuration_issue`
3. `binary_rule_issue`

可能出現：

```json
{
  "composition_model_issue": true,
  "score_configuration_issue": false,
  "binary_rule_issue": false
}
```

表示主要問題是片段分類。

也可能：

```json
{
  "composition_model_issue": false,
  "score_configuration_issue": true,
  "binary_rule_issue": false
}
```

表示分類本身合理，但類別分數設定不合理。

也可能多項同時成立。

沒有足夠證據時必須使用 null，不得強行歸因。

---

# 二十九、證據充分性

輸出：

`evidence_sufficient`

表示：

> 現有輸入是否足以可靠評估 Composition。

如果只提供：

* `Text Of Class Of Most Pieces`
* `Text Of Class Of Highest Score`

而沒有逐一列出所有片段內容，

不能宣稱：

> 已逐片驗證全文所有片段。

但也不能因此機械式判定需要人工複核。

應判斷：

> 目前的資訊缺口是否實質影響 Composition 正確性的判斷。

---

# 三十、人工複核的核心目的

`human_review_required` 的主要用途是：

> 找出值得研究員重新檢查，而且對分類模型或系統優化具有實質價值的案例。

人工複核判定因素依重要程度排序：

1. **Composition 是否正確。**
2. **是否存在片段錯分或漏分。**
3. **是否存在系統性分類偏差。**
4. **是否使用過度寬泛或不適當類別。**
5. **Class Of Most Pieces 是否合理。**
6. **Class Of Highest Score 是否合理。**
7. **聚合 InfoScore 是否與文章實際投資安全價值明顯矛盾。**
8. **在可驗證時，類別分數設定是否不合理。**
9. **二元議題規則是否可能存在問題。**
10. **聚合統計是否存在數學異常。**

其中：

> Composition 正確性始終是決定是否需要人工複核的最高權重因素。

---

# 三十一、human_review_priority

只能使用：

* `"none"`
* `"low"`
* `"medium"`
* `"high"`

## high

Composition 高度可能錯誤，而且案例對模型優化具有明顯價值。

## medium

存在實質性的片段分類、Composition 或可確認的類別分數設定問題。

## low

Composition 整體合理，但存在值得抽查的邊界問題、聚合分數疑點或二元規則疑點。

## none

沒有明顯值得人工複核的問題。

---

# 三十二、不要過度觸發人工複核

如果：

* Composition 高度合理；
* 代表文本與分類一致；
* 沒有具體錯分訊號；
* 聚合分數與文章實際投資安全價值大致一致；
* 只有非常輕微或理論上的不確定；

則：

`human_review_required = false`

不要因為：

> 「沒有看到每一個原始片段」

就一律送人工。

人工複核應聚焦於：

> 真正可能揭露模型或系統問題的案例。

---

# 三十三、suspected_correct_composition

如果現有證據足以合理推測更正後的 Composition，可以輸出：

```json
{
  "Informative": 5,
  "Exempt": 2
}
```

若無法知道每一類實際片段數：

`null`

禁止猜測數量。

---

# 三十四、模型優化意見必須分開

## composition_optimization_hint

只針對：

> 片段分類模型與 Composition。

例如：

`"模型可能過度將軍事評論與軍事事實片段集中判入同一寬泛類別，建議檢查相關分類決策邊界。"`

若無具體問題：

`null`

---

## score_configuration_optimization_hint

只針對：

> 類別分數設定。

只有當分數可驗證或有足夠證據時才可提出具體類別建議。

例如：

`"CrossStrait Relation 在本案例可推知為高負分，但文本屬明確需注意的臺海軍事風險資訊，建議重新檢查該類別的分數方向，或評估是否應由更細緻的軍事風險類別承接高正分。"`

若多類別混合、無法知道各類別分數：

不得指定：

> 哪個類別分數設定錯誤。

可改為：

`"文章整體聚合分數與文本投資安全價值方向不一致，但因無法還原各類別分數，建議檢查相關 Composition 類別之分數設定。"`

如果仍不足以提出有意義建議：

`null`

---

## binary_rule_optimization_hint

只針對：

> 文章層級二元議題規則。

沒有實際規則資訊時不得自行猜測。

---

# 三十五、評估信心

## composition_confidence

範圍：

`0.00–1.00`

表示：

> 對 Composition 正確性判斷的信心。

## confidence

範圍：

`0.00–1.00`

表示：

> 對此次整體自動評估結果的信心。

均不是原分類模型的 confidence。

# 三十七、欄位一致性規則

## composition_correct

* `composition_status = "correct"` → true
* `"likely_correct"` → true
* `"uncertain"` → null
* `"incorrect"` → false

---

## classification_correct

* `"correct"` → true
* `"likely_correct"` → true
* `"uncertain"` → null
* `"incorrect"` → false

---

## composition_model_issue

* 明確存在分類／Composition 問題 → true
* 明確沒有 → false
* 無法判斷 → null

---

## score_configuration_issue

* 可確認特定類別分數設定存在問題 → true
* 可確認分數設定合理 → false
* 無法還原或驗證特定類別分數 → null

---

## binary_rule_issue

* 有足夠證據顯示二元議題規則存在問題 → true
* 有足夠證據顯示正常 → false

只有當：

> 聚合分數可以可靠對應回特定類別分數時，

才為 true。

一般多類別 Composition 且沒有分數表時：

`false`

# 三十八、investment_security_relevance

只能使用：

* `"very_high"`
* `"high"`
* `"medium"`
* `"low"`
* `"none"`

此欄位由你根據文本自行判定：

> 文章本身對臺灣投資安全風險分析具有多少實際研判價值。

它不是原始 InfoScore 的直接翻譯。

---

# 三十九、primary_topic

用一句簡短文字說明文章真正的核心議題。

例如：

`"中共聯合利劍2024B對臺軍演及臺海軍事風險"`

---

# 四十、taiwan_investment_security_link

簡要說明：

> 為什麼此文章與臺灣投資安全有關。

必須指出合理的風險傳導關係。

例如：

`"對臺大型軍演提高臺海軍事衝突、封鎖及灰色地帶風險，可能影響外資信心、航運、供應鏈、半導體生產及企業持續營運。"`

如果實質無關：

`null`

---

# 四十一、composition_reason

這是本任務最重要的理由欄位。

必須優先說明：

* 模型片段分類是否合理；
* Composition 是否合理；
* 哪些類別可能錯分；
* 是否可能漏類；
* Dominant Class 是否合理；
* 是否存在過度寬泛分類；
* 是否存在系統性偏差。

不要主要討論 InfoScore 而忽略 Composition。

---

# 四十二、aggregate_score_reason

此欄位只回答：

> 聚合 InfoScore 的方向及整體表現，是否符合文章實際的臺灣投資安全研判價值。

例如：

`"文章主要涉及臺海軍事風險，屬明確需要注意的投資安全情勢資訊，但 InfoScoreMean 呈現高度負值，因此聚合分數方向與文章實際研判價值存在明顯矛盾。"`

不得在多類別情況下自行指定：

> 哪一個類別造成負分。

---

# 四十三、score_configuration_reason

如果：

`class_score_mapping_verifiable = true`

可以分析特定類別分數。

如果：

`class_score_mapping_verifiable = false`

應明確指出：

> 目前只有 Sum、Mean、Std 及多類別 Composition，無法可靠還原各類別分數，因此不能確認特定類別分數設定是否錯誤。

---

# 四十四、binary_rule_reason

只分析：

> 二元議題規則層是否可能存在問題。

若不知道實際規則：

應說明：

> 現有資訊不足以確認二元議題規則是否正確。

不得依常識自行發明規則。

---

# 四十五、review_reason

如果：

`human_review_required = false`

則：

`review_reason = null`

如果：

`human_review_required = true`

必須具體指出：

> 人工需要確認什麼，以及此案例為何對模型或系統優化有價值。

例如：

`"文章內容明確涉及對臺軍演，但 7 個片段全部判為 CrossStrait Relation，需確認是否存在更精細的軍事風險類別被漏判；此結果可能反映模型過度偏向寬泛兩岸關係類別。"`

或者：

`"Composition 本身大致合理，但全文聚合 InfoScore 為高度負值，與文章明確的臺海軍事投資安全價值相反；由於多類別分數無法從聚合結果還原，建議人工檢查相關類別分數設定。"`

不要只寫：

`"建議人工確認。"`

---

# 四十六、本案例類型的特殊判定原則

若輸入：

```json
{
  "Compositions": {
    "CrossStrait Relation": 7
  },
  "InfoScoreSum": -700,
  "InfoScoreMean": -100,
  "InfoScoreStd": 0
}
```

而文本主要描述：

* 中共「聯合利劍」對臺軍演；
* 解放軍軍事部署；
* 海警在臺灣周邊行動；
* 封控能力；
* 跨戰區軍事活動；
* 情報預警能力；

則應理解：

1. 全文 7 個片段均被判為 CrossStrait Relation。
2. Mean=-100 且 Std=0，因此可可靠推論這些片段取得相同的 -100 分。
3. 這種軍事情勢資訊明確屬於臺灣投資安全需要注意的資訊。
4. 因此合理的聚合分數方向應為正。
5. 現行高度負值與文本投資安全價值明顯矛盾。
6. 可以進一步檢查：

   * CrossStrait Relation 的分數方向是否設定不當；
   * 或是否存在更具體且應為正分的軍事情勢類別，而模型沒有正確分類。
7. 若沒有完整類別樹，不得自行宣稱系統一定存在某一個特定更細類別。

---

# 四十七、最終評估順序

請嚴格按照以下順序進行：

1. 閱讀文本並理解文章實際內容。
2. 判斷文章對臺灣投資安全的實際研判價值。
3. 判斷文章整體合理的聚合分數方向應為正、零、負或混合。
4. 判斷代表性片段的片段類別是否合理。
5. 評估 `Compositions` 是否合理。
6. 檢查是否可能存在錯分、漏分或過度寬泛分類。
7. 評估 `Class Of Most Pieces`。
8. 評估 `Class Of Highest Score`。
9. 檢查 InfoScoreSum / Mean / Std 的聚合統計是否自洽。
10. 判斷聚合 InfoScore 是否符合文章實際的臺灣投資安全研判價值。
11. 判斷現有資訊是否足以還原特定類別分數。
12. 只有在可驗證時，才評估特定類別分數設定。
13. 評估文章層級二元議題結果。
14. 區分問題來源：

    * Composition 模型；
    * Score Configuration；
    * Binary Rule；
    * 多項同時存在；
    * 或無法判定。
15. 決定是否需要人工複核。
16. 分別提出分類模型、分數設定及二元規則的優化建議。

---

# 四十八、人工複核最終核心原則

請始終記住：

> 本任務主要目的，是優化「文章片段類別組成分類模型」。

因此：

> Composition 判定是否可能錯誤，是 `human_review_required` 最重要的決定因子。

如果 Composition 很可能存在：

* 錯分；
* 漏分；
* 過度集中；
* 過度寬泛；
* 主要類別錯誤；
* 系統性分類偏差；

應提高人工複核優先級。

如果 Composition 明確正確，但只有聚合分數或二元規則的小疑點：

> 人工複核優先級通常低於真正的 Composition 錯誤案例。

但若聚合分數與文章實際投資安全價值呈現明顯相反方向，也應留下適當的人工檢查訊號，以協助發現類別分數設定問題。

---

# 四十九、最重要禁止事項

禁止：

> 將 General、APEC、CN Military、R3 等文章層級二元議題視為 Composition 片段類別。

禁止：

> 因為 InfoScoreMean 很高或很低，就反向證明片段分類正確。

禁止：

> 從多類別 Composition 的 Sum / Mean / Std 自行猜測每一種類別的實際分數。

禁止：

> 聚合分數方向異常，就直接斷定某一個特定類別分數設定錯誤。

禁止：

> 把正分理解成「對投資有利」。

禁止：

> 把負分理解成「對投資不利」。

必須理解：

> 正分 = 臺灣投資安全評估需要注意。

> 負分 = 通常無需注意。

> 零分 = 僅依類別難以決定。

> 分數絕對值越大 = 這項判斷越明確。

---

# 五十、待評估資料

以下為文章片段類別組成分類模型的實際輸出：
