我有一個類別層級樹狀結構的 CSV 檔，結構為「母類別,子類別」，想要擴充新類別。

針對【台灣 AI 科技股走勢】，依照既有的類別設計風格，給出合適的類別 label，並接續完成下列工作：

1. 將此類別放入現有層級結構的合適位置，給我完整的中間節點與相關的邊。請比照既有格式，把所有新增的邊收集並存成一個「新增邊.csv」檔，另外如果新增類別與某些既有類別有關係，記得新增邊。所有由 ChatGPT 分析或建議新增的邊，其「備註」欄最後必須統一加上「；＠ChatGPT」，以利與人工新增的類別及關係區分和統計。

2. 把新增類別往上與往下的類別子圖畫出來，分別存成 Markdown（.md）與 PNG 檔，各別提供中文類別名稱版跟英文類別名稱版。

   * 子圖 PNG 請使用美觀、易辨識的配色。
   * 節點內文字應在不超出外框的前提下盡量放大。
   * 圖面風格比照我提供的範例圖。

3. 針對擴增類別的各個底層細緻類別，中文及英文各尋找 100 份新聞、智庫分析報告或研究文章，作為文本分類訓練資料。

   * 理想情況下，每個類別、每個語言版本的文字總長度至少達 10 萬字。
   * 每份資料存成獨立 TXT。
   * TXT 必須放入對應的類別子目錄。
   * 子目錄格式固定為：`#T#[目錄名]`
   * 例如：`#T#[RU-UA MC-Military Aid To UA]`

4. 如果最底層分類太細，導致無法取得足夠資料，可以往上一層類別另外尋找差額資料，以維持足夠的整體訓練資料量。

   例如：A 類別有 A1 與 A2 兩個子類別，理想狀況是 A1、A2 的中文與英文各有 100 份。若中文部分 A1 只有 30 份、A2 只有 60 份，則 A1 尚缺 70 份、A2 尚缺 40 份，可以另外尋找 110 份上層 A 類別的資料補足整體數量。

   但已經取得的 A1 之 30 份仍標註為 A1，A2 之 60 份仍標註為 A2，以保留模型的細緻分類能力。上層類別補充資料則應明確標示其實際對應類別與配額角色。

5. 全部處理完成後，保持原本的 TXT 標註格式及子目錄結構，將下列檔案一起打包成 ZIP 並提供下載：

   * 新增邊 CSV
   * 子圖 Markdown
   * 子圖 PNG
   * 所有類別 TXT
   * 來源清單或資料統計表

6. 最佳情況是直接儲存實際新聞、智庫報告或研究文章的乾淨正文。

   如果因為網站限制、授權、付費牆、機器人驗證、工具限制或其他原因，無法取得實際全文，則改存「公開來源索引與原創分類摘要」，但必須嚴格依照以下兩種格式之一輸出，詳閱下方說明跟參考範例檔：

   A. 單篇文章／單篇報告來源
   B. 搜尋結果集合

============================================================
一、來源紀錄通用規格
==========

1. 每一份 TXT 只能代表一筆來源紀錄。

2. TXT 第一行必須是：

   `#T#[底層類別名稱]`

3. 第一行前面不得有任何其他文字或空白行。

4. 類別目錄名稱也必須是：

   `#T#[底層類別名稱]`

5. 中文與英文資料都應維持相同的核心欄位結構。

6. 所有網址都必須輸出為「純文字完整網址」，不得使用 Markdown 超連結格式。

   正確：

   `原文／索引連結：https://example.com/article`

   錯誤：

   `原文／索引連結：[https://example.com/article](https://example.com/article)`

7. 欄位名稱必須依本模板固定使用，不得任意改成：

   * 新聞網址
   * 參考網址
   * 搜尋頁
   * 資料來源連結
   * 文章頁面
   * 其他未定義名稱

8. 若已取得單篇文章或報告的直接網址，必須優先輸出為「單篇來源」，不要改成搜尋結果集合。

9. 搜尋結果集合只能作為無法取得足夠單篇來源時的備援。

10. 不得把網站首頁、新聞頻道首頁、分類頁、標籤頁或一般搜尋首頁當作單篇文章來源。

============================================================
二、A 類型：單篇文章／單篇報告
================

若已找到可直接開啟的新聞、智庫報告、研究文章或分析報告網址，必須輸出為單篇來源紀錄。

【中文固定格式】

#T#[底層類別名稱]

語言版本：中文

記錄類型：單篇來源

資料單位：公開來源索引與原創分類摘要（不含新聞／報告全文）

配額角色：底層直接樣本／上層補充樣本

對應底層類別：底層類別名稱

主要母類別：直接母類別名稱

所有母類別：由近至遠列出完整母類別路徑

來源標題（原文）：文章或報告的原始標題

來源網站：來源網站網域

來源型態：新聞媒體／智庫報告／研究機構報告／公司公告／其他實際來源型態

來源語言索引：中文

發布時間：可確認的發布日期；無法確認時寫「未確認」

蒐集日期：YYYY-MM-DD

原文／索引連結：https://實際單篇文章或報告網址

中文分類摘要：

請用重新撰寫的文字說明此來源為何支持該底層類別，並列出主要分類線索、主題範圍及使用界線。

【英文固定格式】

#T#[Fine-grained label]

Language version: English

Record type: single source

Data unit: public source index and original classification summary; no article or report body is reproduced

Quota role: direct fine-grained sample / parent-category supplement

Intended fine-grained label: Fine-grained label

Primary parent label: Direct parent label

All parent labels: Complete parent-label path, ordered from nearest to farthest

Source title: Original article or report title

Source domain: Source domain

Source type: news media / think-tank report / research report / corporate filing / other actual source type

Indexed source language: English

Publication date: Confirmed date; use “Unconfirmed” if unavailable

Collection date: YYYY-MM-DD

Original or index URL: https://direct-article-or-report-url

English classification summary:

Explain in newly written text why the source supports the intended fine-grained label. Include the main matching cues, category scope, and usage boundary.

三、B 類型：搜尋結果集合
=============

只有在無法取得足夠的單篇文章或報告網址時，才可以用搜尋結果集合補充候選來源。

目前搜尋結果集合只允許使用 Bing News 搜尋。

允許的網址格式：

https://www.bing.com/news/search?q=查詢詞...

中文搜尋建議加入：

&setlang=zh-tw

英文搜尋建議加入：

&setlang=en-us

不得使用以下網址作為搜尋結果集合：

* https://www.bing.com/search?q=...
* https://www.google.com/search?q=...
* https://news.google.com/search?q=...
* 搜尋引擎首頁
* 網站內部搜尋頁
* 其他未明確支援的搜尋引擎或一般網頁搜尋網址

搜尋結果集合的必要規則：

1. 每份 TXT 只能放一個 Bing News 搜尋索引網址。

2. 不要在同一份 TXT 中另外列出多個候選文章網址。

3. 後續程式會自行展開 Bing News 搜尋結果，再逐篇抓取候選文章正文。

4. 搜尋頁本身不是單篇新聞，不得將搜尋頁摘要、導覽列或結果集合文字當成正文。

5. 來源型態必須固定包含下列文字：

   `公開新聞搜尋索引；候選來源集合，非單篇全文`

6. 記錄類型必須固定寫成：

   `搜尋結果集合`

7. 來源網站必須寫成：

   `bing.com`

8. 原文／索引連結必須是純文字 Bing News 搜尋網址。

9. 若已取得候選文章的直接網址，應將每篇文章各自建立為一份「單篇來源」TXT，不要繼續包在搜尋集合紀錄內。

10. 搜尋關鍵字應直接對應該 TXT 所屬底層類別，避免使用過於寬泛或與類別無關的查詢。

【中文固定格式】

#T#[底層類別名稱]

語言版本：中文

記錄類型：搜尋結果集合

資料單位：公開新聞搜尋索引與原創分類摘要（不含新聞全文）

配額角色：候選來源集合／底層資料補充

對應底層類別：底層類別名稱

主要母類別：直接母類別名稱

所有母類別：由近至遠列出完整母類別路徑

來源標題（原文）：公開新聞索引：[搜尋主題簡述]

來源網站：bing.com

來源型態：公開新聞搜尋索引；候選來源集合，非單篇全文

來源語言索引：中文

發布時間：候選結果涵蓋期間；無法確認時寫「未確認」

蒐集日期：YYYY-MM-DD

原文／索引連結：https://www.bing.com/news/search?q=查詢詞&setlang=zh-tw

中文分類摘要：

說明本次搜尋所使用的主要查詢詞、目標底層類別、預期取得的候選新聞範圍，以及此紀錄只是搜尋索引、不是單篇新聞全文。

【英文固定格式】

#T#[Fine-grained label]

Language version: English

Record type: search-result collection

Data unit: public news-search index and original classification summary; no article body is reproduced

Quota role: candidate-source collection / fine-grained data supplement

Intended fine-grained label: Fine-grained label

Primary parent label: Direct parent label

All parent labels: Complete parent-label path, ordered from nearest to farthest

Source title: Public news index: [brief search-topic description]

Source domain: bing.com

Source type: public news-search index; candidate-source collection, not a single article

Indexed source language: English

Publication date: Candidate-result date range; use “Unconfirmed” if unavailable

Collection date: YYYY-MM-DD

Original or index URL: https://www.bing.com/news/search?q=query+terms&setlang=en-us

English classification summary:

Explain the search terms, intended fine-grained label, expected candidate-news scope, and clarify that the record is a search index rather than a single article.

四、資料品質與數量要求
===========

1. 優先使用可信賴的新聞媒體、智庫、研究機構、政府機關、交易所、上市櫃公司公告或產業研究來源。

2. 同一網址不得在同一底層類別重複建立多份 TXT。

3. 同一篇文章若同時符合多個底層類別，可以在不同類別中使用，但每份分類摘要必須針對該類別重新說明。

4. 不得捏造不存在的文章標題、網址、發布日期或來源網站。

5. 無法確認發布日期時，明確寫「未確認」或 “Unconfirmed”，不得臆測。

6. 搜尋結果集合不能直接計算為已取得的單篇全文數量；只有後續成功展開並抓到的候選文章，才能計入正文資料量。

7. 若實際抓取正文失敗，應保留失敗紀錄與原因，不得把搜尋頁、登入頁、驗證頁、廣告頁或網站導覽文字冒充正文。

8. 最終 ZIP 應包含資料統計，至少列出：

   * 各底層類別中文單篇來源數
   * 各底層類別英文單篇來源數
   * 各底層類別搜尋結果集合數
   * 各底層類別成功取得正文數
   * 各底層類別正文總字數
   * 失敗或受限來源數與原因

9. 如果因工具限制無法真正下載全文，必須誠實說明，不能把原創摘要宣稱為原始新聞全文。

10. 全部資料完成後，保持目錄結構與檔名規格，打包成 ZIP 並提供下載。
